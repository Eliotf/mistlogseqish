# Review guide: M2 chunk 2.3, bullets and indenting

For a senior engineer reviewing this change. It explains what was built, why each choice was made, how to verify it, and where the risks are. Find the commit with `git log -- docs/reviews/2.3-bullets-review.md`.

## Context in two minutes

Mist's editor is one paragraph per line of raw markdown text. Mistlog keeps that text Logseq-compatible: a bullet is `- ` after leading **tab characters** (AGENTS.md invariant 4). Before this change, Tab left the editor (the browser default), Enter just split lines, and bullets were plain grey `- `.

This chunk adds Logseq's keys and look, without changing the text:

- Tab and Shift+Tab indent and outdent, with children
- Enter continues bullets
- Backspace outdents
- bullets are drawn as dots, with indentation guides

## Behaviour

| Key | Situation | Result |
|---|---|---|
| Tab | any line, or a selection | Indent the line(s) and their children by one tab, at most one level below the line above. Plain selected lines become bullets. Tab is always kept in the editor. |
| Shift+Tab | indented line(s) | Outdent with children. Top-level lines in a mixed selection stay put. |
| Enter | bullet, caret in or after the content | Split with `tr.split`. The new line gets the same-level `- `, or a child-level `- ` at the end of a line with children. |
| Enter | bullet, caret before the content | Insert an empty bullet above. |
| Enter | empty bullet | Outdent; at the top level, the line becomes plain and empty. |
| Enter | plain line | Left to TipTap (a normal split). |
| Backspace | caret right after `- ` | Outdent with children; at the top level, remove the `- `. |
| any | suggest mode | Tab and Shift+Tab swallowed with no change; Enter and Backspace left to Mist. |
| any | IME composing | Ignored. |

## Design decisions to validate

1. **Plans are pure, and edits are prefix-only** (everything except Enter splitting). That makes them easy to test exhaustively, and guarantees the rest of a line, with its marks, is untouched.
2. **Inserted indentation never carries marks.** It uses `replaceWith(schema.text(...))`, not `insertText`. All of Mist's marks are currently non-inclusive, so `insertText` would also work today. The test uses a test-only inclusive mark to guard against future ones (found by mutation testing; see below).
3. **Enter uses `tr.split`,** so text moving to the new bullet keeps suggestion, comment and future link marks (tested).
4. **Suggest mode is hands-off** (owner-approved). Indentation changes cannot be expressed as CriticMarkup suggestions yet; F34 is to design that UI. Tab is still swallowed, so the caret never leaves the editor unexpectedly.
5. **Display only.** The `-` stays in the text and is drawn transparent, with a `•` over it. Tabs are real characters with `tab-size`. Arrow keys move one character at a time, so crossing `- ` takes two presses (checked in Chrome). Skipping them is a possible later improvement.
6. **Children stop at an empty line.** That matches how a blank line ends a block in Logseq files, and avoids indenting unrelated text below a gap.

## How to verify

```sh
npm ci
npm run typecheck && npm run lint && npm run test && npm run build
npx vitest run tests/unit/lib/bullets.test.ts tests/unit/lib/bullet-editing.test.ts
```

Expected: 747 tests pass. Coverage is about lines 72.1%, branches 62.9%, functions 68.4%, statements 70.0%. `bullets.ts` is at 100%.

**Checks already run by the author:**

- **Mutation testing.** Each change below broke at least one test:
  - children not moving with their line
  - no depth limit
  - Tab indenting in suggest mode
  - Enter rebuilding text without marks
  - inserted indentation inheriting marks. This one first **survived**, because Mist has no inclusive marks; the test now uses an inclusive test mark.
- **Headless Chrome with real key events,** through the DevTools Protocol `Input.dispatchKeyEvent`, on a page under `npm run dev`:
  - typing `- one`, Enter, `two`, Tab, Enter, `three`, Shift+Tab gave exactly `- one` / `\t- two` / `- three`
  - 3 dots and 1 guide were drawn, and focus stayed in the editor
  - ArrowLeft from the start of "two" moved one character per press (3, 2, 1, 0)
  - no console errors

  The first attempt hit a dev-only Vite re-bundle (`new dependencies optimized: @radix-ui/react-switch … reloading`), which gave React "Invalid hook call" errors. A second run was clean. This is recorded in AGENTS.md.
- **jsdom limit:** character deletion on Backspace is native browser behaviour, so the suggest-mode Backspace test only asserts that the extension does not outdent or remove the bullet.

## Review checklist

- [ ] Every plan only rewrites line prefixes, apart from split and insert-above, and applies edits last line first.
- [ ] The caret ends where the user expects after each key (tested). Check multi-line selections after Tab.
- [ ] No key handler can throw. Plans return null rather than throwing on odd input.
- [ ] Suggest mode: no structural change sneaks in untracked.
- [ ] Decorations skip code fences, and never change the text.
- [ ] Mobile: no Tab key. These commands (`indentSelection`) are exported, for the phone toolbar (F17).

## Known limitations

- **No indentation suggestions in suggest mode** (F34).
- **Arrow keys step over `- ` one character at a time.**
- **Pasting multi-line indented text** keeps whatever indentation it has: spaces are not converted to tabs.
- **No Tab key on phones** until the F17 toolbar.

## Questions for the reviewer

1. Should arrow keys and Home treat `- ` as a single unit, as Logseq effectively does?
2. Should pasting convert leading spaces to tabs, to keep files Logseq-valid?
