# Review guide: 2.5c, pasting links

For a senior engineer reviewing this change. Find the commit with `git log -- docs/reviews/2.5c-pasting-links-review.md`. It builds on 2.5b; read `docs/reviews/2.5b-editable-links-review.md` first.

## What this step does

Pasted or dropped text containing `[[Title]]` is linked at once, by the same rules as leaving a link you typed:

- **A journal date** links to that day.
- **An existing title** (ignoring case) links to that page.
- **A new title** creates an empty page and links to it.

Links copied from Mistlog keep their page ID, because the copied HTML carries the mark. If the page can't be had (offline), the text stays dashed and links the next time the cursor passes through it.

## Design decisions to validate

1. **New titles create pages on paste** (Logseq's behaviour and the prototype's). A large paste can create many pages, each looked up once per title.
2. **Only the pasted range is examined.**
   - `pastedRanges(trs)` maps each step's changed range in a `uiEvent: "paste"` or `"drop"` transaction to the final document.
   - Unlinked `[[...]]` elsewhere in the page is left alone. It links when the cursor passes through it.
3. **Same machinery as typing.** `linkPasted` uses `lookUp` (one request per title at a time) and `applyLink` (marks every unlinked span with that title, except one being edited). Journal dates are linked locally.
4. **Suggest mode and remote transactions** are excluded, by the same guards as the rest of `appendTransaction`.

## How to verify

```sh
npm run typecheck && npm run lint && npm run test && npm run build
```

All four must exit 0; check exit codes, not just the "passed" count. Expected: 865 tests pass, and the floors are raised to 80 / 72 / 79 / 78.

**Checks already run by the author:**

- **A real paste in Chrome.** A genuine `ClipboardEvent` carried `see [[New title]] and [[Oct 28th, 2026]]`:
  - both were linked at once
  - the new page exists in the index (empty, with its slug)
  - there were no console errors
- **Mutation testing:** 5 mutations, all caught. They covered:
  - not linking on paste
  - linking the whole document
  - re-looking-up copied links
  - ignoring drops (caught once a drop test was added)
  - sending journal dates to the server

## Review checklist

- [ ] `pastedRanges` maps positions correctly through later steps and transactions, including when other plugins append transactions after the paste.
- [ ] A paste that ends with the cursor inside a `[[...]]` leaves that span to settle on leave.

## Known limitations

- **No visible summary** of pages created by a paste. The prototype showed "created X" in a toast; there's no toast system yet.
- **Import (F31)** is not built; it will reuse these rules.
