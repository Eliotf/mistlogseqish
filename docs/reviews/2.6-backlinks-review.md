# Review guide: 2.6, backlinks (linked references)

For a senior engineer reviewing this change. Find the commit with `git log -- docs/reviews/2.6-backlinks-review.md`.

## What this step does

Below every page and journal day there is now a **"Linked references · n"** section:

- **Grouping:** pages that link here, most recently updated first.
- **Lines:** each group shows its linking lines as the index last saw them, without the indent or bullet. Links in them show current titles.
- **Opening:** clicking a page or link opens it; Cmd/Ctrl+click opens it in the side panel.
- **Empty pages** say so.
- **Freshness:** the section loads on open and again when you return to the tab.

## Decisions (owner-approved)

1. **Read-only snapshots, not live editors.** Editable references would need a connection per linking page. They are F36, later.
2. **Only the linking line,** with no parent bullets or nested lines, because the index stores only that line (F36).
3. **Not in the feed or the side panel,** to keep those light.
4. **Unlinked references are F35,** later.

## How to verify

```sh
npm run typecheck && npm run lint && npm run test && npm run build
```

All four must exit 0. Expected: 891 tests pass, and the floors are raised to 80 / 73 / 80 / 79.

**Checks already run by the author, in headless Chrome against `npm run dev`:**

- **Two references:** a page was linked from another page and from today's journal (written as a format-4 Yjs client). The target page showed "Linked references · 2", with today's journal first and then the untitled source. The API agreed.
- **After a removal and a rename:** the linking line on the source page was deleted, the target was renamed, and the page reloaded. It showed "Linked references · 1", and the remaining reference shows the new title.
- **No console errors.**
- **Mutation testing:** 10 mutations, all caught. They covered:
  - the bullet being shown
  - brackets not being split out
  - out-of-range marks being trusted
  - other marks being returned as links
  - blank journal titles
  - no refresh on return, or a refresh while hidden
  - a failed refresh wiping the list
  - Cmd being ignored
  - the stored title being shown instead of the current one

## Review checklist

- [ ] Each page view makes one `WorkspaceAgent` request, plus one per return to the tab. There is no polling.
- [ ] References lag the linking page by about 0.3 s, the index delay. A link typed in another tab appears when you return to this tab, not live.
- [ ] Permissions (M4) will need filtering in this route: AGENTS.md invariant 5.

## Known limitations

- **Mist's markdown styling** (bold and so on) isn't shown in reference lines; they're plain text with links.
- **References aren't live** while you stay on the tab.
