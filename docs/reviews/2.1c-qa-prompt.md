# QA prompt: M2 chunk 2.1c, journal pages

Paste everything below the line into a coding model that has access to this repository (for example Claude Code, Codex or Cursor), opened at the repo root.

You are doing independent quality assurance on a change made by another AI model. Your job is to find real defects, not to restate what the code does. Be skeptical: assume there are bugs until you have checked. This change creates documents implicitly (on first text) and deals with dates and time zones, so look hard at creation edge cases, persistence, and anything date-related.

## The project

Mistlog is a Logseq-style notes app forked from Mist (Cloudflare Workers, Durable Objects, React Router 7, TipTap, Yjs). Each page is a `DocumentAgent` Durable Object with a Yjs document. A workspace index tracks pages. Titles are server-owned. Each day has a journal page: the agent named `journal-YYYY-MM-DD`, at `/journal/YYYY-MM-DD`, titled by its date.

Journals are created by their first real text, not by a `POST`, and nothing is persisted before that. "Today" is decided in the browser's time zone.

Read these first, in order:

1. `AGENTS.md`: repo rules, invariants and gotchas, especially journals and "today".
2. `PRD.md`: F1, and the decision log entries dated 2026-10-26.
3. `docs/technical-architecture.md`: "Journal Pages", "Page Titles" and "Workspace Index".
4. `docs/reviews/2.1c-journal-pages-review.md`: the author's review guide, including the `onConnect` bug they found and fixed.
5. `docs/prototype/mistlog-demo.html` (open it in a browser): the agreed journal behaviour.

## What to do

1. **Run the checks** and report the exact results: `npm ci`, `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`. Also run the date tests under at least three `TZ` values, including one with a half-hour offset (for example `Asia/Kolkata`) and one on a daylight-saving changeover date.
2. **Check the requirements.**
   - A journal is created only by real text.
   - Nothing is persisted or indexed before that.
   - Indexing must never affect editing or delay a tab receiving its document.
   - Titles are server-owned.
   - "Today" is never decided on the server.

   Flag any mismatch.
3. **Try to break creation and persistence.** Add tests in `tests/integration/agents/journal-qa.test.ts`, copying the mocking approach from `document-agent.test.ts`. Explore at least:
   - text that is only non-breaking spaces, zero-width characters, or a newline inside a paragraph
   - text added and then deleted in the same transaction
   - text arriving in the client's initial SyncStep2 on connect, as opposed to a later update
   - a CriticMarkup-marked insertion as the first text
   - two clients typing at once on different connections
   - a client typing, then the agent being re-instantiated before the next update: is anything lost?
   - creation while the index is unreachable: is the journal still created, saved and later registered?
   - `POST` to a journal ID (as Mist's home page code might): what happens?
   - comments or threads added to a journal before it is created
4. **Try to break dates.**
   - `localDate` at local midnight
   - daylight-saving changeovers
   - years 1000 and 9999
   - `weekdayOf` across centuries
   - `/journal/:date` with `0000-01-01`, `2026-1-5`, leading zeros or spaces, extra path segments, and encoded characters
   - `isJournalTitle` and `journalTitle` round trips for every day of a leap year
   - what the server and the browser each render for "Today" around midnight in a time zone far from UTC: any hydration warning? Any moment where the page says "Today" for the wrong day?
5. **Check the `onConnect` fix.** Confirm SyncStep1, SyncStep2 and awareness are sent before `indexOnOpen`, and that no other code on the connect or update paths can throw before the client is served. Read `ensureInitialised` and the update handler with that in mind.
6. **Review the tests themselves.** Find assertions that would pass even if the behaviour broke. Mutation-test a few lines of `createJournalIfWritten`, the update handler's early return, `indexOnOpen` and `JournalHeading`. Run the tests, then put each one back.

## Rules

- Do not change production code in `app/`, `agents/`, `workers/` or `wrangler.jsonc`. Only add test files. If a test you write fails because of a real bug, keep it, mark it with `it.fails(...)` and add a comment explaining the bug, so the suite stays green.
- Do not lower coverage floors or weaken existing tests.
- Do not run `wrangler deploy`, `npm run deploy`, or anything against a Cloudflare account. Local `npm run dev` is fine.
- Do not commit or push. Leave changes in the working tree for a human to review.
- Do not report style preferences, or the known limitations in the review guide, unless you think one is more serious than the author claims. If so, say why.

## Report format

Start with one line: the check results (typecheck, lint, tests in each time zone, coverage, build).

Then list findings, most severe first. For each:

- **Severity**: high (lost journal text, a journal created or indexed with no text, a tab that doesn't receive its document, or the wrong day shown as today), medium (a confusing state in a case users will hit), or low (unlikely edge case, or a test gap).
- **Where**: `file:line`.
- **What**: one sentence.
- **Evidence**: the steps or input, the expected outcome and the actual outcome, or the name of the failing test in your QA file.
- **Suggested fix**: one or two sentences.

Then a short section, "Tests that would not catch a regression", listing weak assertions you found.

End with "Not checked": anything you could not verify, and why. For example, real browser hydration across time zones.

If you find no real defects, say so plainly. Do not invent findings to fill the report.
