# QA prompt: 2.5b, typing and editing links

Paste everything below the line into a coding model that has access to this repository, opened at the repo root.

---

You are doing independent quality assurance on a change made by another AI model. Find real defects; do not restate the code.

The change makes links work like Logseq: a link is `[[Title]]` text, and the title carries a `wikilink` mark with the target page's ID. With the cursor between the brackets it is plain text; when the cursor leaves, the text decides what it links to, creating pages as needed.

The worst outcomes are:

- text lost, duplicated or changed without the user doing it
- a link pointing at the wrong page
- duplicate pages for one title
- anything that loops or floods the server

Treat these as high severity.

Read first:

1. `AGENTS.md`, the invariants and gotchas
2. `PRD.md` section 6.1, and the 2026-10-28 decisions
3. `docs/technical-architecture.md`, "Links"
4. `docs/reviews/2.5b-editable-links-review.md`

## What to do

1. **Run the checks:** `npm ci`, `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`. Report exact results.
2. **Try to break settling.** Add tests in `tests/unit/lib/wikilink-qa.test.ts`, using real TipTap and Yjs as `tests/unit/lib/wikilink-editing.test.ts` does. Explore:
   - Nested or odd brackets: `[[a [[b]] c]]`, `[[[x]]]`, `[[x]]]]`, `[[ ]]`.
   - Two links on a line with the same or different titles, and leaving one directly into the other.
   - Undo and redo across entering, editing and leaving a link, and across a rewrite on entry.
   - Selecting across a link and typing over it, cutting it, or deleting it.
   - Enter inside a link, which splits the line.
   - Bullet keys (`app/lib/bullet-editing.ts`) on `\t- [[x]]`.
   - Multi-character or emoji titles.
3. **Concurrency.** Use two `Y.Doc`s and two editors syncing through updates.
   - Both cursors enter the same renamed link: confirm and characterise the known duplication.
   - One tab edits a link while another types elsewhere on the line.
   - One tab settles a link while the other deletes its bracket.
   - Remote edits must never trigger this tab's settling or rewriting.
4. **Asynchronous answers.** Delay `linkPage`. While it is pending:
   - edit the same text again
   - delete it
   - type the same title elsewhere
   - destroy the editor

   Check that nothing wrong gets marked, there are no errors after destroy, and nothing is requested twice for one title.
5. **The server.**
   - Read `app/routes/api.pages.ts` and `DocumentAgent.createWithTitle`.
   - Look for ways to create duplicate pages for one title, orphan persisted pages, or bypass title rules (normalisation, journal titles, invisible characters).
   - Check that `POST /api/pages` cannot be triggered cross-site without JSON.
6. **Suggestions.**
   - Stale answers, Escape, then typing again.
   - Tab versus Enter.
   - Mouse selection keeps focus.
   - Does the list ever stay open after blur or navigation?
   - Is the list element cleaned up when editors are destroyed? The feed creates many.
7. **If you can run headless Chrome against `npm run dev`:**
   - Type links with `Input.insertText`, including IME (`Input.imeSetComposition`) inside `[[`.
   - Check click versus cursor placement, and Alt+Enter.

## Rules

- Only add test files. Revert any temporary changes and leave no diff.
- If a test you write fails because of a real bug, keep it, mark it with `it.fails(...)`, and add a comment explaining the bug.
- Do not lower coverage floors or weaken tests.
- Do not deploy or touch any Cloudflare account. Do not commit or push.

## Report format

Start with one line: the check results.

Then list findings, most severe first. For each:

- **Severity**: high, medium, or low.
- **Where**: `file:line`.
- **What**: one sentence.
- **Evidence**.
- **Suggested fix**.

Then "Not checked". If you find no real defects, say so plainly.
