# Review guide: 2.5b, typing and editing links (with 2.5a reworked)

For a senior engineer reviewing this change. Find the commit with `git log -- docs/reviews/2.5b-editable-links-review.md`.

## What this step does

After trying 2.5a, the owner asked for Logseq's interaction instead of links as solid units:

- A link is `[[Title]]` text. When the cursor is between its brackets, it's plain text you can edit.
- When the cursor leaves, the text decides what the link points to.

This commit replaces 2.5a's "one unit" behaviour and adds creating links. 2.5a's old-tab guard, title store and titles route are unchanged.

What you can now do:

- **Type `[[`.** The closing `]]` is added for you, with title suggestions. Choose with Enter or Tab, close with Esc, and type `]` to step out.
- **Edit a link's text, then move away.** The link follows the text:
  - **The same page** if the text is unchanged, or only its case changed.
  - **Another page or a journal** if the text names one.
  - **A new empty page** if no page has that title.
  - **Plain text** if the title is emptied or a bracket is deleted.
- **Click a link** to open its page (Alt+Enter from the keyboard).
- **Renamed links:** a link to a renamed page shows the new title. Its stored text changes only when your cursor enters it.

## Design decisions to validate

1. **Brackets are stored text** (owner-approved). Typing, deleting and copying work as normal text. Export already needs `[[Title]]`. No live page had links before this step, so nothing needs migrating. The old bracketless format exists only in tests.
2. **Only one automatic text change: rewriting a renamed link on entry** (owner-approved).
   - **Why it's needed:** with the cursor inside, you must see the text you're editing, so the hidden stale copy has to become the current title.
   - **When it happens:** in `appendTransaction`, when the focused cursor enters the link.
   - **What it does:** replaces the title, keeping its marks, with `addToHistory: false` (y-tiptap honours it, [y-tiptap.js:2099](../../node_modules/@tiptap/y-tiptap/dist/y-tiptap.js)).
   - **Remaining risk:** two cursors entering the same renamed link within one sync round trip would duplicate that title.
3. **Relinking only sets or removes marks.**
   - Concurrent tabs converge on the same formatting.
   - The asynchronous answer from `POST /api/pages` is applied by searching for unlinked spans with that title, not by stored positions. It skips the span still being edited.
   - Lookups are de-duplicated per title.
4. **"Unchanged" uses a snapshot.** Plugin state records the span's text on entry (`entry`), and leaving compares against it. A rewrite on entry updates the snapshot (the `REWRITTEN` meta), so a rewritten link isn't treated as edited.
5. **The reveal region is strictly inside the brackets.** It runs from just inside `[[` to just inside `]]`, and only applies while the editor is focused. The positions just outside a link aren't "in" it, so typing `]` steps out and settles the link at once.
6. **Creating pages is race-safe.**
   - `POST /api/pages` answers journal dates locally, then existing titles.
   - Otherwise it calls `DocumentAgent.createWithTitle` on a fresh ID. That claims the title in the index under the page's index lock *before* writing anything. If another tab won, it returns that tab's page and the fresh object persists nothing.
7. **Clicks:** mousedown on a link you aren't editing is cancelled, so clicking opens the page without moving the cursor in. Clicks inside a link you're editing place the cursor as normal.
8. **Suggest mode:** display and opening only, with no rewrite, relinking or auto-pairing (as with bullets; F34).

## Review checklist

- [ ] `appendTransaction` ignores remote (y-sync) transactions, so other people's edits never trigger settling or rewriting in this tab.
- [ ] Settling and relinking run only in the tab whose cursor left a link. Other tabs don't act on links they merely see.
- [ ] The asynchronous `applyLink` can't mark the wrong text. It marks only unlinked spans whose title matches the requested key, and never the span being edited.
- [ ] `createWithTitle` on a taken title calls `ensureInitialised()` (creating the empty table) but persists no document state. That leaves an empty object with a table, which costs nothing meaningful.
- [ ] Suggestions are fetched with a 120 ms debounce and drop stale answers (`suggestFor`). Each query wakes `WorkspaceAgent` once.
- [ ] The `focus` and `blur` handlers dispatch transactions; check nothing loops (meta-only transactions don't change entry unless the span changes).

## Known limitations

- **Pasting `[[Title]]`** isn't converted until you move through it. That's 2.5c, which will reuse settling.
- **Search** finds links by their stored text (PRD F13).
- **The suggestions list has no `aria-activedescendant` link to the editor,** so screen readers don't announce the highlighted option. To do with the phone toolbar and accessibility pass.
- **IME composition inside `[[`** and **phone selection** haven't been tried on real devices.
- **Two cursors entering the same renamed link at once** would duplicate its title (decision 2).
