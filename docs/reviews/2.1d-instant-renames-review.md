# Review guide: M2 chunk 2.1d, instant renames

For a senior engineer reviewing this change. It explains what was built, why each choice was made, how to verify it, and where the risks are. It revises parts of 2.1a (titles) and 2.1b (readable URLs); read `docs/reviews/2.1a-page-titles-review.md` and `docs/reviews/2.1b-readable-urls-review.md` first. Find the commit with `git log -- docs/reviews/2.1d-instant-renames-review.md`.

## Context in two minutes

After 2.1a and 2.1b, a rename reached the workspace index on the 2-second reindex throttle. That had three effects:

- reloading straight after a rename could show the old address
- the browser address only updated on the next load
- two renames to the same title within those 2 seconds could both pass the uniqueness check

The owner asked for faster renames. This chunk:

1. **Renames through the server.** `POST /api/rename` claims the title in the index atomically and returns the new address, and the browser moves to it straight away.
2. **Re-indexes immediately on title change.** Other edits keep the 2-second throttle.

## Rename sequence

1. The user presses Enter or leaves the title.
2. `PageTitle` runs `normalizeTitle` locally, then POSTs `{ pageId, title }` to `/api/rename`.
3. The route runs `normalizeTitle` again, then calls `WorkspaceAgent.claimTitle`, which runs in one transaction and returns the slug.
4. The route returns `{ ok: true, title, path }`.
5. `PageTitle` sets `meta.title` in the page's Yjs doc. The edit syncs to the `DocumentAgent` and other tabs.
6. `DocumentLayout` navigates, with replace, to `path`. The `/page/<slug>` loader resolves immediately, because the slug already exists.
7. `DocumentAgent`'s `meta` observer calls `reindexNow`, and the index's title, slug and full-text entry are confirmed from the document.

## Design decisions to validate

1. **The index learns the title before the document does.** The document stays the source of truth. If step 5 never happens (the tab closes, or the sync fails), the next reindex sends the document's title and `assignSlug` moves the slug back. A claimed but never-saved title stays as a redirect slug for that page, which is harmless.
2. **`claimTitle` does not touch `updated_at` or `pages_fts`.** That keeps the stale-update ordering from 1.5 intact. Full-text search sees the new title once step 7 reindexes, within milliseconds.
3. **There is a transient flip.** A reindex already in flight with the old title can land after the claim, briefly making the old slug current again, until step 7 lands. This is tested: the final state is correct, and both slugs resolve throughout, either directly or by redirect.
4. **The Yjs observer order mattered.** Map observers run before the document's `update` event, so when the title observer fires, `markForIndex` has not yet set `dirty`. `reindexNow` marks dirty itself. A mutation test confirms that removing this breaks the immediate-reindex test.
5. **`reindexNow` calls `reindex()` directly.** It does not use `schedule(0)`, which would add alarm latency. An already-pending scheduled reindex later finds `dirty: false` and returns. Overlap is safe because `reindex` clears `dirty` synchronously before its first `await`.
6. **JSON-only rename.** It forces a CORS preflight for cross-site requests, so a plain HTML form on another site cannot rename pages. Cloudflare Access is the main protection; this is defence in depth.
7. **Navigation uses React Router `navigate(replace)`, not `history.replaceState`.** The router's location stays correct and the loader confirms the new address. `DocumentScreen` is keyed by page ID, so the editor is not remounted.
8. **Typing stays on the 2-second throttle** (owner-approved). Revisit when search and backlinks arrive.

## How to verify

```sh
npm ci
npm run typecheck && npm run lint && npm run test && npm run build
npx vitest run tests/unit/routes/rename.test.ts tests/unit/components/page-title.test.tsx tests/unit/agents/workspace-index.test.ts tests/integration/agents/document-agent.test.ts
```

Expected: 586 tests pass. Coverage is about lines 65.3%, branches 55.9%, functions 58.2%, statements 63.0%.

Manual check in a browser (`npm run dev`):

1. Rename a page. The address bar should change straight away.
2. Reload immediately; the page should load at the new address.
3. Open a second page and try the first page's title. It should be refused.

**Checks already run by the author:**

- **Mutation testing.** Each of these broke at least one test:
  - `reindexNow` not marking the edit
  - not reindexing on title change
  - `claimTitle` ignoring clashes
  - the route accepting form posts
- **End to end on this machine** (`npm run dev`), with results:

  | Check | Result |
  |---|---|
  | Claiming a taken title | Refused, with the holder's title |
  | Claiming a free title | Returned `/page/fresh-notes`, which answered **200 immediately** |
  | A form post | 415 |
  | Setting `meta.title` over the Yjs WebSocket (as another tab would) | `/page/instant-title` answered 200 in **236 ms**, including script start-up |
  | The page's previous slug | Redirected to the new one |

## Review checklist

- [ ] `claimTitle` is a single transaction, and no path can give two pages the same `title_key` through renames.
- [ ] A failed or abandoned rename never leaves the browser on an address that does not resolve.
- [ ] `reindexNow` can never throw into the Yjs observer, and cannot run for unindexable documents.
- [ ] The rename route validates everything before calling the index. Nothing user-controlled reaches SQL except as bound parameters.
- [ ] Removing `/api/title-check` leaves no callers (`grep -r title-check app`).

## Known limitations

- **Titles set directly over Yjs, bypassing `/api/rename`, skip the uniqueness check.** A malicious client could do that. For normal use, the index's reindex accepts what the document says. That is acceptable while single-user and behind Cloudflare Access.
- **Typing is still throttled at 2 seconds** for search, backlinks and tasks.
- **No automated test covers the navigation in `DocumentLayout`.** Rendering the route needs the full editor stack; it is covered by the manual check above.

## Questions for the reviewer

1. Should `DocumentAgent` reject `meta.title` changes the index has not claimed, so uniqueness is enforced even for direct Yjs writes? That would need the document to ask the index, or the index to push claims to documents.
2. Should a claimed-but-never-saved title expire, rather than lingering as a redirect slug?
