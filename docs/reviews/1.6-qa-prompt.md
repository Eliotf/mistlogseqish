# QA prompt: 1.6, index rebuild

Paste everything below the line into a coding model that has access to this repository, opened at the repo root.

---

You are doing independent quality assurance on a change made by another AI model. Find real defects; do not restate the code.

The change makes the workspace index rebuild itself:

- **Trigger:** on waking, if registered pages have no index entry or one built by an older parser, `WorkspaceAgent` starts a pass.
- **Steps:** each step, run by `this.schedule`, asks 10 pages' `DocumentAgent.refreshIndex()` to re-index. It saves a cursor and schedules the next step until none are left.
- **Nothing is cleared first.**

Read first:

- `AGENTS.md` (especially the Durable Object gotchas)
- `docs/technical-architecture.md` "How it stays correct"
- `docs/reviews/1.6-index-rebuild-review.md`

## What to do

1. **Run the checks:** `npm ci`, `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`. Report each exit code.
2. **Add tests in `tests/integration/agents/rebuild-qa.test.ts`.** Cover:
   - a step that throws outside the per-page `try` (does the rebuild stall forever?)
   - pages registered mid-pass, both before and after the cursor
   - a page deleted from the registry mid-pass
   - two instances (an eviction mid-pass)
   - `refreshIndex` on a page whose index updates are failing (the retry backoff)
   - a rebuild running at the same time as a page's normal reindex
3. **Check Durable Object rules:**
   - no repeating timers
   - nothing keeps an object awake
   - scheduled work never deletes data
   - the rebuild can't be triggered from a browser
4. **Look for a deadlock risk** in `WorkspaceAgent` awaiting a `DocumentAgent` RPC that calls back into `WorkspaceAgent`.

## Rules

- Only add test files. Revert any temporary changes and leave no diff.
- If a test you write fails because of a real bug, keep it, mark it with `it.fails(...)`, and add a comment explaining the bug.
- Do not lower coverage floors or weaken tests.
- Do not deploy or touch any Cloudflare account. Do not commit or push.

## Report format

Start with one line: the check results, with exit codes.

Then list findings, most severe first. For each:

- **Severity**: high, medium, or low.
- **Where**: `file:line`.
- **What**: one sentence.
- **Evidence**.
- **Suggested fix**.

Then "Not checked". If you find no real defects, say so plainly.
