# Review guide: M2 chunk 2.1b, readable URLs

For a senior engineer reviewing this change. It explains what was built, why each choice was made, how to verify it, and where the risks are. It builds on 2.1a (titles) and the workspace index (1.4, 1.5); their guides are in `docs/reviews/`. Find the commit with `git log -- docs/reviews/2.1b-readable-urls-review.md`.

## Context in two minutes

Pages now have titles (2.1a). This chunk gives titled pages readable addresses, `/page/meeting-notes`.

- `/docs/<id>` stays the permanent address and redirects to the readable one.
- Old slugs keep redirecting after a rename.
- The workspace index assigns and remembers slugs.

This chunk includes **the index's first schema migration**, which runs on the live index the first time the new code opens it.

The owner may revisit whether readable slugs are worth their complexity, and likes `/docs/<id>` as the canonical source for portable markdown export (PRD open question 3).

## Slug assignment rules

For page P with title T, `base = slugify(T)`:

1. If `base` is empty: P has no current slug (its old slugs stay as redirects), and its address is `/docs/<id>`.
2. If P's current slug is already one of the candidates `[base, base-<first 4 of id>, base-<id>]`, keep it. This keeps re-indexing stable, even for a suffixed slug.
3. Otherwise, take the first candidate that is free, already P's, or only another page's *old* redirect. Mark P's other slugs not current, and upsert this one as current.

`slugs` primary key is `slug`; each row is `(slug, page_id, current)`. A page has at most one current slug.

## Design decisions to validate

1. **Slug history is never cleared** (owner-approved). Like `registry`, `slugs` is excluded from `DERIVED_TABLES`, because old slugs cannot be recovered from documents. The trade-off: the index is no longer fully derivable. Two tables now hold state that matters.
2. **Unicode slugs, accents kept** (owner-approved). `café-notes` is percent-encoded in `Location` headers (`pagePath` uses `encodeURIComponent`). React Router decodes route params. `resolveSlug` normalises to NFC and lowercase.
3. **The address updates on the next load, not instantly** (owner-approved). After a rename, the browser stays on its current URL. That avoids an address that 404s during the roughly 2 seconds before the index catches up.
4. **A real title beats a leftover redirect.** If page A was "Notes" and is renamed, then page B named "Notes" takes `/page/notes`. Old links to A's "Notes" then reach B. This is consistent with links following titles, but surprising if someone bookmarked A at its old address.
5. **Canonical redirects.** Any non-current form redirects to the one canonical address: an old slug, different case, or a decomposed accent that differs after NFC. This was found in end-to-end testing: `/page/PROJECT-PLANS` was returning 200.
6. **`/docs/<id>` fails open.** If the slug lookup throws, the page loads at `/docs/<id>`, and the error is logged. `/page/<slug>` has no fallback, because it depends on the index. An index outage shows the error page there.
7. **Backfill order.** The migration slugs pages in page-ID order. Two pages whose titles clash (for example "Meeting Notes" and "Meeting notes!") are decided by ID, not by age.
8. **Migration framework.** One transaction covers the version 1 statements, `INSERT OR IGNORE` of version 1, and every pending migration with its version bump. A failure rolls everything back, leaving the version at 1 (tested with a trigger). An index newer than the code throws, which protects against deploying old code over a newer index.

npx vitest run tests/unit/lib/slug.test.ts tests/unit/agents/workspace-index.test.ts tests/unit/routes/page-routes.test.ts

Expected: 567 tests pass. Coverage is about lines 65.0%, branches 55.3%, functions 58.2%, statements 62.6%. The only uncovered line in `workspace-index.ts` is the unreachable "No free slug" throw.

**Checks already run by the author:**

- **Mutation testing** on `agents/workspace-index.ts`. Each of these broke at least one test:
  - no takeover of old redirects
  - slugs not kept stable on re-index
  - rebuild clearing slugs
  - schema version not recorded after migrating
  - an old slug staying current after a rename
- **Cloudflare runtime.** A version 1 index was built inside local `workerd` (Miniflare) with SQLite-backed Durable Object storage, then opened with the new code. It migrated to version 2 and slugged both pages (one accented). Rename and resolve behaved as tested, and reopening did not migrate again.
- **End to end on this machine, on a real existing version 1 index** left by the 2.1a check. Under `npm run dev`:
  - the index migrated to version 2 on first use
  - `/docs/tttt1111` → 302 to `/page/project-notes` → 200
  - an untitled page stayed at `/docs/<id>` → 200
  - after renaming over the Yjs WebSocket, `/page/project-notes` → 302 to `/page/project-plans`
  - an accented title → `/page/caf%C3%A9-notes` → 200
  - an unknown slug → 404
  - the header showed `/page/project-plans`

  `/page/PROJECT-PLANS` returned 200, which led to decision 5. That fix is covered by unit tests but was not re-run end to end.

## Review checklist

- [ ] The migration is safe on the live index: it is idempotent and transactional, it skips pages with empty titles and journals, and it fails closed on newer schemas.
- [ ] `assignSlug` cannot leave a page with two current slugs, and a slug can never belong to two pages.
- [ ] Every redirect target is built with `pagePath`, so slugs are always encoded. No open redirect is possible, because targets are always site-relative paths built from the index.
- [ ] `/docs/<id>` still works when the index is down; `/page/<slug>` fails visibly.
- [ ] No app code imports from `agents/`; `document-loader.server.ts` is server-only.
- [ ] `page.$slug.tsx` re-exports the screen from `docs.$id.tsx`, so both routes render the identical component. Check that the loader data shapes match.

## Known limitations

- **Journal addresses** (`/journal/YYYY-MM-DD`) are chunk 2.1c.
- **The address does not update after a rename** until the next load (decision 3).
- **Takeover can retarget old links** (decision 4). Merge pages (F32) and deletion will need to revisit this.
- **There is no index-down fallback for `/page/<slug>`.**
- **The rebuild order can differ from the original order,** which could change which of two clashing titles gets the plain slug. The old slugs still redirect.

## Questions for the reviewer

1. Should decision 4 instead keep old redirects pointing at their original page, and give the new page a suffixed slug?
2. Should redirects from `/docs/<id>` be 301 (permanent) instead of 302? Today the target changes on rename, which is why 302 was chosen.
3. Is keeping two non-derived tables (`registry`, `slugs`) acceptable, or should slug history move into each page's Yjs doc, so the index is fully derivable again?
