# QA prompt: 2.5c, pasting links

Paste everything below the line into a coding model that has access to this repository, opened at the repo root.

---

You are doing independent quality assurance on a change made by another AI model. Find real defects; do not restate the code.

The change links `[[Title]]` text as soon as it is pasted or dropped into the editor, creating pages for new titles.

The worst outcomes are:

- wrong links
- duplicate pages
- requests that repeat or flood the server
- text changed by the paste handling

Treat these as high severity.

Read first: `AGENTS.md`, `PRD.md` 6.1, `docs/technical-architecture.md` "Links", and `docs/reviews/2.5c-pasting-links-review.md`. Build on `docs/reviews/2.5b-qa-prompt.md` for context.

## What to do

1. **Run the checks:** `npm ci`, `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`. Report each **exit code**, not just the test counts.
2. **Add tests in `tests/unit/lib/wikilink-paste-qa.test.ts`,** using real TipTap and Yjs. Stub `ClipboardEvent` as the existing tests do. Explore:
   - multi-line pastes
   - pasting over a selection that contains links
   - pasting inside an existing `[[...]]`
   - pasting HTML from other apps (Logseq, Roam, Google Docs) with brackets split across elements
   - pasting HTML with a `data-page-id` for a page that doesn't exist
   - undo straight after a paste while a lookup is still pending
   - pasting 200 different new titles: how many requests, and does anything break?
3. **Concurrency.** Two editors on one `Y.Doc` pair, both pasting the same new title at once. Check that `POST /api/pages` and `createWithTitle` still give one page.
4. **If you can run headless Chrome against `npm run dev`:** dispatch real `ClipboardEvent`s with a `DataTransfer` carrying plain text and HTML.

## Rules

- Only add test files. Revert any temporary changes and leave no diff.
- If a test you write fails because of a real bug, keep it, mark it with `it.fails(...)`, and add a comment explaining the bug.
- Do not lower coverage floors or weaken tests.
- Do not deploy or touch any Cloudflare account. Do not commit or push.

## Report format

Start with one line: the check results, with exit codes.

Then list findings, most severe first. For each:

- **Severity**: high, medium, or low.
- **Where**: `file:line`.
- **What**: one sentence.
- **Evidence**.
- **Suggested fix**.

Then "Not checked". If you find no real defects, say so plainly.
