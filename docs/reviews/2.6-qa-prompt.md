# QA prompt: 2.6, backlinks

Paste everything below the line into a coding model that has access to this repository, opened at the repo root.

---

You are doing independent quality assurance on a change made by another AI model. Find real defects; do not restate the code.

The change shows "Linked references" below each page and journal day, from `GET /api/pages/backlinks`, as read-only snapshots of the linking lines.

Read first: `AGENTS.md`, `PRD.md` F4 and the 2026-10-31 decision, `docs/technical-architecture.md` "Linked references", and `docs/reviews/2.6-backlinks-review.md`.

## What to do

1. **Run the checks:** `npm ci`, `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`. Report each exit code.
2. **Add tests in `tests/unit/lib/backlinks-qa.test.ts(x)`.** Explore:
   - lines with several links to different pages
   - a link to the page itself
   - links whose stored marks don't line up with the text (old index rows)
   - tabs and emoji before a link
   - a group with 100 lines
   - a missing page in a reference
   - a page linking here from a line inside a code fence
3. **Check the index side** (`agents/workspace-index.ts`, `backlinks`):
   - ordering
   - self-links
   - a page that links here twice on one line
   - what happens after the linking page is deleted or re-indexed with the link removed
4. **Check the route** for input validation, and that it only returns data for pages in the index. Note anything that will matter for permissions (M4).
5. **If you can run headless Chrome against `npm run dev`:**
   - Link a page from several places and check the section.
   - Rename the target and the linking pages.
   - Check Cmd/Ctrl+click and the empty state.

## Rules

- Only add test files. Revert any temporary changes and leave no diff.
- If a test you write fails because of a real bug, keep it, mark it with `it.fails(...)`, and add a comment explaining the bug.
- Do not lower coverage floors or weaken tests.
- Do not deploy or touch any Cloudflare account. Do not commit or push.

## Report format

Start with one line: the check results, with exit codes.

Then list findings, most severe first. For each:

- **Severity**: high, medium, or low.
- **Where**: `file:line`.
- **What**: one sentence.
- **Evidence**.
- **Suggested fix**.

Then "Not checked". If you find no real defects, say so plainly.
