# Review guide: 2.5d, the side panel

For a senior engineer reviewing this change. Find the commit with `git log -- docs/reviews/2.5d-side-panel-review.md`.

## What this step does

Cmd/Ctrl+click on a link, or Alt+Shift+Enter with the cursor in one, opens that page in a right-hand side panel, as in Roam:

- **The stack:** pages stack newest first, at most 10. Each is a live editor with its title (click it to open the page in the main view) and a close button.
- **Hiding and closing:** `t` then `r`, outside text fields, shows or hides the panel. ✕ in the header closes every page.
- **Pages with comments:** the panel takes the comments column's place, at the owner's choice. Its "Comments" button hides the panel so comments return.
- **Phones:** a full-screen sheet with Back.
- **Remembered:** the panel survives reloads in the same browser.

This completes links (2.5).

## Design decisions to validate

1. **One provider for every screen,** in `app/root.tsx`, so the panel survives navigation. The panel sits beside the whole route, header included, as Roam's right sidebar does.
2. **Storage without hydration trouble.**
   - Panel state lives in a small store read through `useSyncExternalStore`, whose server snapshot is empty.
   - The first approach, restoring in an effect, was rejected by lint (cascading renders).
   - Storage that is blocked or holds rubbish falls back to an empty panel.
3. **The `side` flag travels on the existing `wikilink-open` event.** `ConnectedEditor` decides between the panel and navigation. Missing pages navigate instead, because the panel would show an editor for a page that doesn't exist.
4. **Capped at 10.** Each page is a live connection to its Durable Object. Hidden tabs still disconnect after 5 minutes (`useDisconnectWhenHidden`).
5. **`t r` ignores modifier keys, text fields and contenteditable**, and needs `r` within 1 s of `t`.

## How to verify

```sh
npm run typecheck && npm run lint && npm run test && npm run build
```

All four must exit 0. Expected: 879 tests pass. Coverage stays above the floors (80 / 72 / 79 / 78).

**Checks already run by the author, in headless Chrome against `npm run dev` at 1440 px:**

- Cmd+click on a link opened the panel with that page. The comments column was hidden and the URL was unchanged.
- Typing in the panel's editor saved to that page; the index reported it as having content.
- "Comments" hid the panel and brought comments back. `t r` brought the panel back.
- A reload kept the panel.
- At 390 px the panel covered the screen (390×844 at 0,0).
- There were no console errors, and a screenshot confirmed the layout.

**Mutation testing:** 10 mutations, all caught. They covered:

- the cap
- showing on open
- `t r` while typing
- a slow chord
- remembering
- side clicks navigating instead
- missing pages going to the panel
- Cmd being ignored
- Alt+Shift+Enter
- the Comments label

## Review checklist

- [ ] Opening the same page in the main view and the panel gives two editors on one document. Yjs keeps them in sync; check that nothing else assumes one editor per page (comment highlights, presence).
- [ ] The panel's editors register their own link handling, so clicking a link inside the panel navigates the main view, and Cmd+clicking one stacks it.

## Known limitations

- **The comments column being hidden while the panel is open is only checked in the browser,** not by a unit test: `DocumentLayout` needs heavy mocking.
- **The panel header is a few pixels shorter than the app header.** Cosmetic.
- **No left sidebar yet** (F8, chunk 2.8). `t l` doesn't exist.
