# Review guide: M2 chunk 2.2, the journal feed

For a senior engineer reviewing this change. It explains what was built, why each choice was made, how to verify it, and where the risks are. It builds on 2.1c (journal pages) and the faster indexing in `docs/reviews/1.5b-index-after-pause-review.md`, which shipped alongside it. Find the commit with `git log -- docs/reviews/2.2-journal-feed-review.md`.

## Context in two minutes

The home page (`/`) becomes the journal feed, as in the prototype. Today's journal is at the top, ready to type in, with earlier days that have notes below. The owner's brief was "it should feel like scrolling in Roam":

- every day is editable in place
- older days load as you scroll
- per-day Mist controls are a compact bar

Mist's landing page (demo document, onboarding, drag-and-drop upload) is replaced. The `/new` endpoint stays for scripts.

## Design decisions to validate

1. **Every day is a live editor** (owner-approved, "like Roam"). Each costs one WebSocket, one `Y.Doc`, one TipTap editor and one `DocumentProvider` (with `useThreads`). Days connect 1200px early and never disconnect, so a long scroll accumulates connections. That is fine for weeks of days; for months it may need disconnecting far-off days.
2. **Today is decided in the browser.** The server renders a placeholder slot and the earlier days; the browser inserts today. This avoids hydration mismatches; the headless Chrome check saw no hydration warnings.
3. **Days come from the index.** The index learns of new writing about 0.3 seconds after a pause (the companion change), so a day just written in appears in the list on the next load almost immediately. Today is always shown regardless.
4. **The compact bar** (owner-approved). Toggling suggest mode on a day sets it for that day's document for everyone, as Mist's mode toggle always has. Comments and threads are not available in the feed.
5. **Refactor before reuse.** `AppHeader` and `ConnectedEditor` were extracted first, and the full suite passed unchanged (664 tests) before any feed code was added.

## How to verify

```sh
npm ci
npm run typecheck && npm run lint && npm run test && npm run build
npx vitest run tests/unit/components/journal-feed.test.tsx tests/unit/components/journal-day.test.tsx tests/unit/routes/journals-api.test.ts tests/unit/components/feed-pieces.test.tsx
```

Expected: 701 tests pass. Coverage is about lines 70.2%, branches 61.1%, functions 66.4%, statements 68.2%.

**Checks already run by the author:**

- **jsdom timing, with real editors.** 15 real TipTap editors with Yjs and Mist's markdown decorations, 40 lines each:
  - mounting took 187 ms in total, about 12.5 ms each
  - typing in one with all 15 mounted: median 0.6 ms per keystroke, 95th percentile 1.4 ms, worst 4.3 ms
- **Headless Chrome against `npm run dev`,** with 15 journal days created through the Yjs WebSocket. Driven by a small dependency-free DevTools Protocol script.
  - After the page's JavaScript started, today ("Oct 27th, 2026") was on top, with 7 earlier days and 6 live editors.
  - Scrolling to the bottom loaded all days through infinite scroll: 17 days, **17 live editors**.
  - **No long tasks over 50 ms** while scrolling.
  - **No console errors or hydration warnings.**
  - The first attempt timed out before the JavaScript started, because of Vite's dev-server cold start. Production uses built assets.
- **Not measured:** typing feel in a real browser with many days live. Please try it after deploy.

## Review checklist

- [ ] Hooks run only in `LiveDay`, so a placeholder day opens no connection.
- [ ] No setState inside an effect body. Observer callbacks only, as the React hooks lint rule requires.
- [ ] The feed never shows today twice, or future days.
- [ ] `loadOlder` cannot run twice at once, and stops after a short batch.
- [ ] Keyboard path: "Show older days" and "Try again" are buttons; the date and "Open day" are links; edit and suggest are buttons with `aria-pressed`.
- [ ] `/api/journals` validates its parameters before calling the index, and every response is JSON.

## Known limitations

- **Live days are never disconnected,** so memory and connections grow with very long scrolls.
- **No comments or threads in the feed;** they are on the day's own page.
- **Mist's onboarding, demo document and drag-and-drop upload are gone from `/`.** The files remain unused.
- **Today does not roll over at midnight** if the feed stays open overnight; reloading fixes it.

## Questions for the reviewer

1. Should far-off days disconnect (for example more than 20 days away) to bound resources on long scrolls?
2. Is the 1200px connect margin right? Earlier means less waiting but more connections.
