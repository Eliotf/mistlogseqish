# Review guide: 2.5a, showing links

For a senior engineer reviewing this change. Find the commit with `git log -- docs/reviews/2.5a-showing-links-review.md`.

## What this step does

Links (`wikilink` marks with a `pageId`, defined in M1) now display in the editor. Nothing in the UI creates them yet: that is 2.5b. This step ships first so that the old-tab guard is live before any link exists.

- **Current titles:** a link shows the target page's current title, styled as in the prototype. Empty pages get a grey underline, missing pages a dashed one, and journals are set in mono.
- **One unit:** a link moves and deletes as one unit.
- **Opening:** click, or Alt+Enter just after a link, opens the page. Cmd/Ctrl+click does the same until the side panel (2.5e).
- **Copy:** plain-text copy writes `[[Current Title]]`.
- **Older tabs:** tabs running code from before this format are refused and asked to reload.

## Design decisions to validate

1. **Show the current title over the stored copy; never rewrite the copy** (owner-approved).
   - Rewriting on open was rejected for these reasons:
     - two tabs would both rewrite, and Yjs keeps both insertions (`BooksBooks`)
     - in suggest mode the rewrite would appear as a suggestion
     - it would sit in undo history
     - it would move comments anchored to the text
     - it would wake the page's Durable Object
     - it would edit pages just by viewing them, against PRD 6.1
   - Cost: displayed text differs from stored text. The editor handles that by hiding the stale copy (`font-size: 0`, `aria-hidden`) and drawing a widget, and by keeping the cursor out of links.
   - The stale copy is only hidden after a rename. Most links show their copy as normal styled text.
2. **The guard lives in the Worker, not only the agent.**
   - Verified: y-tiptap deletes text it cannot convert ([y-tiptap.js:894-899](../../node_modules/@tiptap/y-tiptap/dist/y-tiptap.js)). A regression test shows an editor without the mark empties the line.
   - Old code can't contain a check that only new code has, so the server must refuse.
   - A close inside `DocumentAgent.onConnect` never reached the client: partyserver calls `onConnect` before returning the 101 handshake ([index.js:363](../../node_modules/partyserver/dist/index.js)), and the close is lost.
   - So `workers/app.ts` answers the handshake itself (`WebSocketPair`, `accept`, `close(4001)`). As a bonus, refusals never wake the page's Durable Object, even when old tabs retry.
   - The agent still refuses, sending nothing, as a second line of defence.
3. **The browser stops retrying on 4001.**
   - PartySocket schedules a reconnect *before* dispatching `close`, so `useYjsEditor` calls `socket.close()` in its listener, which cancels it.
   - Verified in Chrome: one attempt, no retries over 25 s, the status shows "Updated: reload", and the editor is read-only.
4. **Opening a link is a DOM event, not a callback.**
   - React's lint rule forbids refs during render, and options are fixed when TipTap creates the editor.
   - So the extension fires a cancelable `wikilink-open` event on the editor element, and `Editor` turns it into `navigate()`.
   - If nothing handles it, it falls back to `location.assign`. This also keeps each feed day's editor separate.
5. **Arrow keys step one character when leaving a link's edge.** Without this, Chrome's own move landed in the hidden copy and mapped back to the same position, wasting a key press. This was found in the browser probe. Surrogate pairs are kept whole.
6. **One title store per browser** (`pageTitles()`). It batches requests in a microtask, fetches each ID once, refreshes on `visibilitychange`, and keeps old titles if a fetch fails. Live updates are F33.
7. **`pagesByIds` chunks at 100.** Durable Object SQLite allows 100 bound parameters per query; Node's SQLite in tests does not enforce this. A test wraps `db.exec` to assert no query binds more than 100.
8. **Search is unchanged** (owner-informed). Full-text search indexes the stored copy, so a renamed link is still found by its old title. Fixing it properly belongs with search. It is noted in PRD F13.

## Review checklist

- [ ] Nothing in the browser can now create a link, so this step cannot cause the deletion it guards against, even before the guard.
- [ ] The Worker check runs before `routeAgentRequest`, matches only `/agents/document-agent/<id>` upgrades, and cannot block the workspace path, other routes, or `/new` (`/new` uses RPC, not WebSockets).
- [ ] Deploying will refuse every tab open before the deploy, since none send `format`. It's a one-off. Old tabs retry with PartySocket's backoff, answered by the Worker without waking a Durable Object.
- [ ] Hidden text with `font-size: 0`: IME input and phone selection near a stale link are untested on real devices.
- [ ] `keepCursorOutside` runs in `appendTransaction` on every transaction. It's O(links) per call, since `linkRanges` walks the document. That's fine at notes scale; worth watching on very long pages.
- [ ] Mode check in `remove()`: Backspace in suggest mode falls through to the suggest-mode plugin, so a link loses characters as suggested deletions. Acceptable until F34.

## Known limitations

- **Search** finds links by their old title (PRD F13).
- **Titles** refresh on load and on returning to the tab, not live (F33).
- **Untested on real phones and with IME input.**
- **Cursor drawing has no automated test.** jsdom cannot measure where a cursor is drawn, so the `side: 1` fix is covered only by the browser probe.
