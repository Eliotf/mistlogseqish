You are doing independent quality assurance on a change made by another AI model. Your job is to find real defects, not to restate what the code does. Be skeptical: assume there are bugs until you have checked. This change puts many live editors on one page, so look at resource use, loading behaviour, hydration and accessibility, not just correctness.

## The project

Mistlog is a Logseq-style notes app forked from Mist (Cloudflare Workers, Durable Objects, React Router 7, TipTap, Yjs). Each journal day is a Yjs document. The home page is now the journal feed:

- today first, then earlier days with notes
- every day a live editor that connects as it nears the screen
- older days loading as you scroll
- a compact Mist bar on each day

Read first:

3. `docs/technical-architecture.md`: "Journal Feed" and "Journal Pages"
4. `docs/reviews/2.2-journal-feed-review.md`
5. `docs/prototype/mistlog-demo.html` (open it in a browser): the agreed feed behaviour

## What to do

1. **Run the checks:** `npm ci`, `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`. Report exact results.
2. **Check the requirements.**
   - Today is always first, decided in the browser.
   - Future days are hidden.
   - Each day is editable in place.
   - Older days load as you scroll, with a keyboard path.
   - The feed still works when the index is down.
   - Every mouse action has a keyboard path.
   - The single-page screen behaves exactly as before the refactor.
3. **Try to break it.** Add tests in `tests/unit/components/feed-qa.test.tsx` and `tests/unit/routes/journals-api-qa.test.ts`. Explore at least:
   - **Initial days:**
     - all future
     - all today
     - duplicates
     - unsorted
     - empty with `loadFailed`
     - a first batch exactly `FEED_PAGE_SIZE` long, followed by an empty batch
   - **Loading:**
     - the sentinel firing several times quickly
     - "Show older days" clicked during a load
     - a fetch failing, then succeeding
     - batches that overlap previous days
     - the component unmounting mid-fetch (React warnings?)
   - **Days:**
     - a day whose `exists` changes after mount
     - the date link and "Open day" pointing at the right address
     - the mode toggle with suggest already on
     - the placeholder's heading level and accessible name
   - **The API:** unusual `before` and `limit` values (negative, huge, decimal, repeated parameters), and the index returning journals with `journalDate: null`.
   - **The refactor:** compare the single-page screen's rendered header and editor props before and after (`git show HEAD~1:app/routes/docs.$id.tsx`). Anything lost?
4. **If you can run a real browser locally** (for example headless Chrome against `npm run dev`), measure:
   - connections and memory with 50+ days
   - typing latency in a day while 30 days are live
   - hydration warnings around local midnight in a time zone far from UTC

   If you cannot, say so under "Not checked".
5. **Review the tests.** Find assertions that would pass if the behaviour broke. Mutation-test lines in `JournalFeed`, `JournalDay` and `api.journals.ts`, then put each one back.

## Rules

- Only add test files. Do not change production code. If a test you write fails because of a real bug, keep it, mark it with `it.fails(...)` and add a comment explaining the bug.
- Do not lower coverage floors or weaken tests.
- Do not deploy or touch any Cloudflare account. Do not commit or push.
- Do not report style preferences or the review guide's known limitations, unless you think one is worse than claimed. If so, say why.

## Report format

Start with one line: the check results.

Then list findings, most severe first. For each:

- **Severity**: high (lost text, today missing or wrong, the feed broken when the index is down, or a resource blow-up in normal use), medium (a confusing or janky experience users will hit), or low.
- **Where**: `file:line`.
- **What**: one sentence.
- **Evidence**: steps or input, the expected outcome and the actual outcome, or the failing test name.
- **Suggested fix**: one or two sentences.

Then "Tests that would not catch a regression", and finally "Not checked".

If you find no real defects, say so plainly. Do not invent findings.
